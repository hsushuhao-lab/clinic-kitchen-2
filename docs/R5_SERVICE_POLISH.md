# R5 病人插畫、需求圖示、E 操作與失誤反應

基準：R4 `1983f8d25ee654c64e191d5a55acd9cc1d925357`。保留叫號、左至右六站、三位可走跑的 Q 版醫師、單一料理工作區、三單晚班及原有動態配樂。不重寫 main.js、不新增菜色。

## 病人與圖像需求
六位病人改用完整核准 NPC 原稿的輪廓裁切，保留各自的髮型、手、服裝與身體；不再將橢圓照片頭貼在同一件襯衫上。左側放大半身插畫，上方坐姿採各自完整上身與補畫腿部的四格微動。它們仍是衍生 2D 圖集，不是六套重新手繪的完整骨架動畫。

病人辣度、蔥花、飯量各有實際 WebP 圖示及短標籤；期望／實際出餐欄位使用相同映射。沒有將僅存在於設定稿的「加豆腐」擅自加入配方。

三張新設定展板用來確認風格、圖像語意與卡通反應。本次可重建的 production 圖像來源為 repository 既有完整核准 NPC/醫師原稿與 R2 圖集；未宣稱三張新展板 PNG 本身已上傳或等同遊戲素材。

## 鍵盤
- 備料：1 豆腐、2 絞肉、3 豆瓣醬、4 蒜、5 青蔥、6 花椒。E 切配／舀取；沒選材料時先選豆腐。Space 既有精準操作保留。
- 炒鍋：F 開關火；E 依序下已備材料，再翻炒。切配及前三次有效翻炒照原規則給精準分，不靠連按刷分。
- 配飯：1 半碗、2 正常飯；E 出餐。診間 E 互動與對話確認維持。
- 需到工作站、完成前置步驟且未暫停；輸入欄、音量 slider、對話與結算不被快捷鍵劫持。手機場景 E 按鈕走同一條動作路徑。

## 4 秒之後仍可烹調
本輪採用的遊戲規則：核心材料就緒並翻炒三次後累積大火時間，滿 4 秒收汁可出餐，但不自動關火。之後每累積完整 1 秒扣 1 個滿意度百分點，最多 20；例如連續 7.2 秒為超時 3.2 秒，扣 3%。原本严重焦鍋仍為 20%，與超時扣分取較大值，避免重複處罰。

F 關火、暫停、閱讀對話、背景分頁停止累積。再開火或補材料不會抹掉已经累積的超時；下一號的新餐點才清零。精準 miss 不會阻止料理完成。

## 不符合需求的卡通反應
任一辣度、蔥花、飯量或火候檢查不符，出餐結果呈現一次玩具軟槌敲頭 → 頭暈星星 → 揉頭 → 恢復的四格演出。三位醫師各自保留原來角色特徵。無血腥、無真實傷害；只是虛構遊戲 slapstick。

分數只依餐點計算一次，不另扣敲頭分。角色位置及遊戲計時在終局保持凍結，只有反應影格可播放。「叫下一號」立即可用，不強迫等待演出；下一位清除反應。完全符合需求不播放敲頭。reduced-motion 顯示靜態揉頭影格。

## 素材與測試
`tools/build_service_art.py` 產生 21 個 RGBA WebP：6 半身、6 坐姿、6 需求圖示、3 醫師反應圖集。`verify_service_art.py` 檢查解碼、透明度、來源與輸出 SHA-256、反應影格差異，並在 QA artifact 產生真正出貨素材的 contact sheet。

保留原 R4 全部 29 個規則測試與 13 組叫號／四張訂單／音訊／手機瀏覽器驗收；新增 5 個規則測試及 7 組 E 鍵、超時、終局、圖片與版面驗收。新增測試以真實鍵盤按鍵操作，不傳送、不修改階段來取代遊玩。

本機 `--inline` 只代表離線瀏覽器。發布必須以相同 commit 的 Runtime-only web release audit 成功及 Public game verification 為準；後者核對 source SHA、所有 runtime 檔案並重新操作 R4 與 R5 測試。技術通過不代表使用者已核准美術質感。
